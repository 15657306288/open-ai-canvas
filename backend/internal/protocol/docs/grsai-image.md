# {{NAME}}

Grsai 图像适配器通过创建任务与查询结果两步完成生成。它有专门的结果数组和违规状态处理，不能直接替换为通用图片解析器。本文基于仓库实现说明使用边界，不保证任意同名渠道都遵守相同接口。

## 接口与鉴权

{{OPERATIONS}}

创建请求使用 JSON，后端渠道负责鉴权。轮询查询参数中的任务 ID 经过 URL 编码，不能直接拼接模型输出的任意 URL。配置渠道时应使用服务根地址，避免把创建路径重复追加到 Base URL。

## 模型与支持边界

模型 ID 来自渠道配置，不由适配器自动切换。`nano-banana` 前缀使用额外的尺寸字段，其余模型沿用当前请求结构。账号是否有权限、实际分辨率和参考图片限制应在渠道侧核实，不通过猜测模型名称补价格或配额。

## 参数与字段映射

{{PARAMETERS}}

创建请求包含 `model`、`prompt` 和固定的 `replyType: "async"`；非空宽高比写入 `aspectRatio`。仅当模型名以 `nano-banana` 开头时，增加 `imageSize`，优先使用宿主 `resolution`，为空时回退到 `quality`。参考图片集合写入 `images`。

当前适配器不会把 GPT 图像模型的宽高比自动换算成像素尺寸，也不发送通用元数据中的所有可选字段。需要指定像素值时应由经过验证的渠道配置提供合法值，而不是在通用表单里猜测。

## 响应、状态与错误

创建响应依次读取 `id`、`task_id` 或 `taskId`，缺少任务 ID 时直接报错。状态 `violation` 明确视为失败，不作为等待继续轮询。错误说明读取响应的错误或消息字段；查询过程使用专门解析器识别 `results` 数组。

执行失败与取消保持终态，不返回假图片。对成功响应应核对结果媒体是否可识别，保存资源前不宣称持久化完成。排查问题时只保留脱敏响应结构，不记录渠道 API Key、Cookie 或完整鉴权头。

## 官方资料与验证边界

最新模型、服务限制与价格请核对所用 Grsai 渠道的官方说明。本文依据 `grsaiImagesAdapter`、`parseGrsaiCreate` 与 `parseGrsaiPoll` 编写，在线接口更新后须新增协议测试，不能只改文档或让失败状态无限重试。
