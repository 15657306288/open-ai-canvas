# 影策插件统一安装契约（Installation Contract）

任何 Agent（Codex / Cursor / Claude 等）按本文件执行安装，目标是「装得上、登得进、验得过、可复现」，
并且在任何一步失败时**停在原地、如实报错，不得谎报成功**。

## 一、前置条件

1. 宿主是一台能打开浏览器完成授权的本地桌面环境。
2. 唯一可信来源：本市场仓库（GitHub `15657306288/open-ai-canvas` 的 `agent-marketplace`，或运营方明确给出的镜像）。不要从聊天记录里的不明链接安装。
3. 开始前完整阅读对应平台文档（如 `docs/codex.md`），不要凭记忆跳步。
4. 用户已持有运营方颁发的客户 API Key（`ak_…`）。

## 二、必完成序列（六步，顺序不可换）

1. **添加市场**：用平台原生命令（Codex：`plugin marketplace add … --sparse agent-marketplace`），禁止手工拷贝缓存文件。
2. **安装插件**：`plugin add yingce@yingce`；安装后用 `plugin list` 确认状态为 `installed, enabled`。
3. **OAuth 登录**：执行 `mcp login yingce`，由**用户本人**在浏览器授权页粘贴客户 Key 并点「同意授权」。Agent 不得代填、代存、猜测该 Key，也不得把它写进任何配置文件或日志。
4. **完整重启**：退出并重启宿主 Agent，让插件与 MCP 连接在全新会话加载。
5. **新任务只读验证**：在全新任务里调用只读工具（`channel_list` / `canvas_get_context`）确认真的返回数据，而不是仅看「已安装」。
6. **能力介绍**：用一两句向用户说明现在能做什么（画布读写、工作流、多渠道生成），并指出详细规范在插件 `skills/`。

## 三、用户安全边界（Agent 不可代劳）

以下动作只能由用户本人完成，Agent 只能指引、不能替代：

- 客户 API Key / 任何密钥的输入、粘贴、保管；
- 浏览器里的授权确认；
- 平台弹出的权限授权、目录授权、重启确认。

Agent 不读取浏览器凭据库、不导出 token、不在回复中回显密钥或访问令牌。

## 四、失败处理（禁止谎报）

- 停在**第一个失败步骤**，输出该步的原始错误信息与正在执行的命令。
- 不删除缓存、不反复重装、不静默换源、不跳过验证步。
- 网络类错误（`Reconnecting…`）先按平台文档配置代理绕过（NO_PROXY），再重试同一命令。
- 授权类错误（Key 无效 / 401 / 402 / 429）如实转述，引导用户联系运营方，不伪造成功结果。
- 只有第 5 步只读验证拿到真实返回，才允许宣布「安装成功」。

## 五、权威更新源

- 插件能力、端点、版本以本仓库 `plugins/yingce/.codex-plugin/plugin.json` 与 `.mcp.json` 为准。
- 升级走平台原生命令（Codex：`plugin marketplace upgrade` 后重新 `plugin add`），不要手改缓存目录。
